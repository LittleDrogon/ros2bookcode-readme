## 1. AI 时代：C/C++ 二次开发待遇总览

AI 降低的是「能编译、能改通」的门槛，不是「能长期负责、能把复杂系统改对」的门槛。  
针对 Firefox、AOSP、内核相关、SDK/驱动等方向的 C/C++ 二次开发，待遇总体上仍**高于多数应用层 CRUD**，但分化很大。

### 1.1 国内大致定位（一线，税前月薪，粗估）

| 层次 | 典型工作 | 大致月薪量级 |
|------|----------|--------------|
| 入门 / 外包改包 | 编译、打补丁、跟文档改配置 | 15–25k |
| 能独立改模块 | 浏览器 / Android 某子系统、稳定性、性能 | 25–45k |
| 能扛线上问题 | 崩溃、兼容、功耗、安全、架构改造 | 45–70k+ |
| 稀缺方向 | 安全、渲染、编译器、虚拟化、车载 / IoT 底层 | 更高，看公司和谈判 |

海外同类（systems / browser / Android platform）年薪常见在中高区间，资深再叠加股票。

### 1.2 AI 之后，谁还会被高薪留？

**AI 容易替代的部分：**

- 按文档编译、找依赖、改小功能、写样板代码

**AI 很难替代、因此仍值钱的部分：**

- **系统级排障**：竞态、内存、ABI、链接、启动链、功耗
- **跨版本 / 跨厂商兼容**：AOSP 碎片化、芯片厂商差异
- **性能与正确性**：渲染、多媒体、网络栈、安全沙箱
- **责任边界**：改坏了谁背锅——这类角色仍要人

结论：只会「跟着 AI 编译通过」的人，待遇会被压；能把 Firefox / AOSP 这类大仓库当日常工作对象、能交付稳定改动的人，门槛表面变低，**筛选其实更严**。

### 1.3 和「普通 C++ 业务开发」比

- **二次开发 / 平台层**：天花板往往更高，但岗位更少、面试更硬、加班和压力常见
- **业务 C++**（游戏、量化、后端高性能）：有时更稳、岗位更多
- 纯「会编译开源项目」本身几乎不构成溢价；溢价在**某个子系统的深度 + 交付记录**

### 1.4 实务结论

1. **待遇仍不错**，尤其能独立改 AOSP / 浏览器 / 驱动 / 中间件并能上线的人。
2. **AI 抬高了下限竞争**：只会跟做的人会变多，中位薪水可能承压。
3. **差异化靠深度**：选一条线 dig deep（例如 Android graphics、浏览器网络栈、相机 HAL、安全），比泛泛「会二次开发」更值钱。
4. **地域与行业差极大**：一线互联网 / 芯片 / 车企 / 泛安全 vs 二三线外包，同能力可能差一倍以上。

## 2. 聚焦 AOSP

AOSP 二次开发在国内属于「**岗位少、门槛高、溢价仍在**」的方向，待遇通常高于普通应用层，但非常看你卡在哪一层。

### 2.1 岗位在做什么（待遇大致递增）

1. **BSP / 移植**：厂商 SoC 适配、启动、驱动、外设  
2. **Framework / 系统服务**：AMS、WMS、音频、相机、显示策略改动  
3. **HAL / Vendor**：Camera、Display、Audio、Sensor 等接口与厂商库对接  
4. **性能 / 稳定性**：ANR、卡顿、功耗、内存、崩溃归因  
5. **安全 / 合规**：SELinux、Verified Boot、TEE、隐私合规  

纯「能编过 AOSP、能改个应用层功能」通常只对到外包 / 项目制；能独立扛**某条竖井（相机、显示、多媒体、车载）** 才谈得上高薪。

### 2.2 一线城市薪资粗估（税前月薪）

以北京 / 上海 / 深圳 / 杭州为主（含大小周差异）：

| 层级 | 能力画像 | 大致区间 |
|------|----------|----------|
| 初级 | 能编译、能跟需求改 Framework 小功能、会看 log | 20–30k |
| 中级 | 能独立改子系统、能解兼容 / 稳定性问题、熟悉构建与分区 | 30–45k |
| 高级 | 能主导模块、对性能 / 功耗 / 相机或显示有深度、能带人 | 45–70k |
| 专家 / TL | 平台架构、车载 Android、芯片原厂平台、安全方向 | 70k+（再加股票 / 签字费） |

补充：

- **手机品牌 / 芯片原厂 / 车企智能座舱** 往往高于纯外包集成商  
- **外包驻场** 名义可能也写 AOSP，实际多是适配与联调，中位会低一截  
- 海外同类（Android Platform / AOSP engineer）资深常见到更高总包，但岗位更集中在大厂  

### 2.3 AI 对 AOSP 行情的实际影响

- **被压价的**：按文档编译、改配置、改 UI/Settings、跟 ticket 打补丁  
- **仍稀缺的**：Camera/Display 管线、功耗与调度、跨 Android 大版本升级、厂商闭源 HAL 联调、量产问题闭环  

AOSP 体量大、版本碎、厂商差多，**「改对且量产不炸」** 仍然是人筛出来的，不是 AI 筛出来的。

### 2.4 更值钱的细分（相对泛 Framework）

优先深度之一即可：

- Camera HAL / 3A / ISP 联调  
- Graphics / SurfaceFlinger / HWC  
- Audio / 多媒体  
- 车载（AAOS）  
- 性能与功耗  
- 安全（SELinux / Keystore / TEE）  

泛 Framework 改业务逻辑的人供给相对多；竖井越深，议价越强。

### 2.5 与设备 / 感知方向的交集

若同时做深度相机 / Orbbec / ROS2，与 AOSP 的 **Camera HAL、多媒体、嵌入式 C++** 有交集。  
从设备 SDK 转到 AAOS / 手机相机平台，比从纯应用转 AOSP 更顺；反过来，纯 AOSP Framework 经验也不自动等于传感器 / 点云方向的溢价。

**一句话**：AOSP 方向国内一线中高级大概 **30–70k** 这一档很常见；真正拉开差距的是子系统深度和量产交付，不是「会不会编 AOSP」。

## 3. AOSP 与 ROS2 机器人开发对比

和 ROS2 机器人开发比：**AOSP 平均薪资上限更高、岗位更少更卷；ROS2 岗位面更宽、入门相对易，但天花板和议价通常低一截**——除非卡在感知 / 控制 / 量产交付这类硬核点上。

### 3.1 直接对比

| 维度 | AOSP | ROS2 机器人 |
|------|------|-------------|
| 一线中高级薪资 | 大致更高（中高级常能摸到更高档） | 中位略低，分布更散 |
| 岗位数量 | 少，集中在手机 / 车机 / 芯片 / 外包 | 更多，机器人公司、AGV、科研、集成商都有 |
| 技术门槛 | 系统体量大、版本 / 厂商碎片重 | 生态散、业务场景杂，但单点上手更快 |
| AI 冲击 | 编译和改小功能被稀释；竖井仍值钱 | 写节点、调包更容易被稀释；现场与系统集成仍难替代 |
| 职业路径 | 品牌 / 原厂 / 车载平台，偏「平台工程师」 | 偏「产品 / 算法+工程」或「系统集成」 |
| 稳定性 | 大厂相对稳，外包波动大 | 创业公司多，融资与项目周期影响大 |

### 3.2 钱和稀缺性

- **AOSP**：卖的是「能在 Android 平台上量产改对」——组织大、责任重、可替代性相对低，同年限往往更能谈高价。  
- **ROS2**：卖的是「能把机器人跑起来并交付」——会 launch、会写节点的人变多了；真正溢价在：
  - 导航 / 定位 / 多机
  - 实时与中间件（DDS、QoS、时钟、性能）
  - 驱动与硬件（相机、雷达、臂、整机联调）
  - 工业现场：稳定性、安全、产线交付

粗线条：同样 3–5 年，一线 **AOSP 中高级** 往往整体高于 **泛 ROS2 应用开发**；但 **ROS2 + 深度相机 / 感知 / 控制 + 量产机器人** 可以追到接近甚至重叠区间，尤其在深圳 / 苏州 / 上海的机器人与具身智能公司。

### 3.3 若已在 ROS2 + 深度相机 / SDK 线

这类人更靠近**机器人里偏底层与感知的工程岗**，不是纯写业务节点：

- 比泛 ROS2 应用开发**更好议价**
- 比纯 AOSP Framework 改业务**岗位选择更多**，但跳到手机原厂 AOSP 时，系统深度可能不够，需要补 HAL / 相机管线
- 若目标是钱：AOSP 相机 / 车载，或机器人公司里的感知 / 平台，都可能更高  
- 若目标是选择面和创业生态：ROS2 侧通常更宽  

### 3.4 怎么选（务实）

- 想要**更高且相对标准化的平台岗薪资**：偏 AOSP（尤其 Camera / 车载）  
- 想要**行业增长叙事 + 硬件产品感 + 岗位多样性**：偏 ROS2 / 机器人  
- 想要两边都沾溢价：**深度相机 / Camera HAL / 嵌入式 C++ / 实时系统**——这是交叉带，比「纯 AOSP 改设置」或「纯 ROS2 写节点」都更抗 AI、更好谈钱

## 4. 有多少人编译过 AOSP

**没有公开精确人数。** Google 不公布「下载 / 编译过 AOSP」的统计。

### 4.1 公开可引用的说法

在 Linux Plumbers 相关讨论里（[LWN 报道](https://lwn.net/Articles/992992/)），有人对**活跃在 AOSP 上的开发者**给过粗区间：

> **大约 1 万～10 万量级**

这里说的是「在做 AOSP 相关工作的人」（移植、定制、厂商适配等），不是「点过一次下载」的人。

### 4.2 把「编译过」拆开看

| 口径 | 大致量级（全球，粗估） | 说明 |
|------|------------------------|------|
| 试过 sync / 看过文档 | 远大于上面 | 很多半途而废（磁盘、网络、机器不够） |
| **完整编通过至少一次** | 可能 **数万～十几万** 累计 | 含学生、外包、刷机玩家、培训班 |
| 工作中经常编、经常改 | **约 1 万～10 万** | 和上面公开估计接近 |
| 能往官方 AOSP 合入代码 | **少得多** | platform 层仍高度集中在 Google 等 |

国内：手机品牌、ODM、芯片原厂、车载、外包加起来，**经常碰 AOSP 的可能是几千到一两万量级**；其中「自己从零完整编通过纯 AOSP」又比「在公司改过厂商 Android 树」更少——很多人编的是**厂商分支**，不是 Google 干净 AOSP。

### 4.3 为什么「编过」的人其实不算多

- 源码体积大（常要数百 GB 级）、编译吃 CPU / 内存、一次全编很久  
- 环境折腾成本高，业余玩家留存差  
- 真正刚需主要在：手机 / 车机 / 芯片 / 定制 ROM，不在普通 App 开发  

### 4.4 和「会不会很稀缺」的关系

- **只编通过一次**：在求职里几乎不构成稀缺，培训班也能带过去  
- **能在厂商树上稳定改、量产交付**：才是那 1 万～10 万里真正被公司付钱的一批  
- 和 ROS2 比：ROS2「跑通过 demo / 写过节点」的人远多于「编通过 AOSP」的人；但 AOSP「编通过」也不等于能拿高薪  

**一句话**：没有官方人头数；业界口头量级是全球 AOSP 从业者大约 **一万到十万**；「人生中完整编通过一次」会更多一些，但仍远少于普通 Android App 或 ROS2 入门用户。

## 5. 「完整编通过至少一次」的量级

### 5.1 更靠谱的口径

一次「完整编过」通常意味着：

- `repo sync` 成功拿到可用源码树  
- `source build/envsetup.sh` + `lunch` + `m` / `make` 之类跑完  
- 产出可刷或可跑的系统镜像（不一定上真机，模拟器也算）  

卡人的硬条件：

- 磁盘常要 **200GB～1TB+**  
- 内存最好 **32GB+**（16GB 很痛苦）  
- 全量编译少则数小时，机器差可到一天  
- 网络 / 镜像 / 依赖翻车率高  

所以这不是「看过教程」的人数，而是「机器和耐心都够、至少成功过一次」的人。

### 5.2 全球累计（AOSP）

结合「AOSP 从业者 1 万～10 万」，再往外扩一圈「试过并成功」的人：

| 估计 | 含义 |
|------|------|
| 偏低：约 **5 万～10 万** | 主要是正式做过 Android 系统 / BSP / 车载 / ROM 的人 |
| 中位：约 **10 万～30 万** | 再加上历年学生、培训、爱好者、外包里跟做过一轮的人 |
| 偏高：到 **50 万** 量级 | 把「厂商内部树编过一次」也算进来，且含很多半正式环境 |

更倾向把 **「纯 AOSP / 接近 AOSP 主线，自己环境完整编通」** 放在：

> **全球累计大约 10 万量级（乐观到二三十万，很难到百万）**

### 5.3 容易高估的点

很多人说「编过 Android」其实是：

- 编过 **厂商 SDK / 部分模块**，不是整树  
- 在公司 **已配好的服务器** 上敲了一下 `make`  
- 编过 **kernel / HAL / 单个 app**，不是整包 system image  

这些人数会明显多于「完整 AOSP 全编译成功一次」。

**一句话**：完整编通过至少一次——全球更像**十万量级**，不是百万；成功过一次说明跨过了环境门槛，但招聘里含金量仍然有限——贵的是能反复改、能稳住、能量产。

## 6. 中国 AOSP，以及 Firefox 全球 / 中国

口径统一为：**完整全量编译成功至少一次**。  
Firefox 指真正 `./mach build` 编过 C++/Rust，**不是** Artifact 模式只下预编译包。

### 6.1 中国：AOSP 完整编通过至少一次

| 口径 | 中国累计粗估 |
|------|----------------|
| 偏紧 | **2 万～5 万** |
| 中位 | **约 3 万～8 万** |
| 偏松（含厂商内部分支整树编过） | **到 10 万上下** |

粗依据：

- 全球 AOSP 从业者公开口头量级约 1 万～10 万，中国占手机 / ODM / 芯片 / 车载很大一块，从业常编的可能就 **几千～一两万**  
- 「人生中成功过一次」再放大学生、培训、外包、刷机 / ROM，大致到 **数万**  
- 国内更多人编的是 **厂商树**，严格「Google 干净 AOSP」会更少一截  

### 6.2 Firefox：完整全量编译

Firefox 比 AOSP 对个人更友好（`mach bootstrap`、机器要求相对低），但真正全量编 libxul 仍要时间和磁盘；很多贡献者只用 Artifact build，不算「完整编译」。

| 口径 | 全球累计粗估 | 中国累计粗估 |
|------|----------------|----------------|
| 偏紧（认真全量编过） | **5 万～15 万** | **几千～1 万** |
| 中位 | **约 10 万～30 万** | **约 0.5 万～2 万** |
| 偏松（含多年历史、短时试过） | **到四五十万** | **到两三万** 已偏乐观 |

辅助线索（不是「编译人数」本身）：

- 历史公开材料里，Mozilla 系常见说法是累计数千量级贡献者、每月数百活跃开发者——那是**往上游交过代码**的人，远小于「编通过」  
- 关系大致是：编通过 ≫ 贡献过 ≫ 能合入主线  

中国更少的原因：

- 桌面浏览器市场以 Chrome / 国内双核为主，Firefox 用户和二次开发需求都小  
- 国内系统岗更多堆在 **Android / 鸿蒙 / 车载**，很少有人靠「改 Firefox」吃饭  
- 爱好者、安全研究员、个别互联网基础软件组会有，但体量远小于 AOSP  

### 6.3 并排一眼看清

| 项目 | 全球「完整编过 ≥1 次」 | 中国 |
|------|----------------------|------|
| **AOSP** | 约 **10 万量级**（乐观二三十万） | 约 **数万**（中位大概 3 万～8 万） |
| **Firefox** | 约 **10 万～30 万** 量级 | 约 **几千到两万**（很难到十万） |

直观结论：

- **全球**：Firefox「完整编过」的人未必比 AOSP 少——个人电脑就能试，门槛更低  
- **中国**：**AOSP 远多于 Firefox**——工作刚需在手机系统，不在桌面浏览器内核  

再次强调：这些都是量级估计，不是普查；招聘里「编通过」本身溢价都很有限，能改、能稳、能量产才值钱。

## 7. 小结

| 主题 | 核心结论 |
|------|----------|
| AI + 二次开发待遇 | 编译门槛下降，真正溢价在深度、排障、量产与责任 |
| AOSP 薪资（一线） | 中高级常见约 30–70k；竖井（相机 / 显示 / 车载 / 安全）拉开差距 |
| AOSP vs ROS2 | AOSP 上限与标准化议价往往更高；ROS2 岗位更宽；交叉带（相机 / 嵌入式 / 实时）两边都沾 |
| AOSP 从业者 | 全球公开口头量级约 1 万～10 万 |
| AOSP 完整编过 ≥1 次 | 全球约十万量级；中国约数万 |
| Firefox 完整编过 ≥1 次 | 全球约 10 万～30 万量级；中国约几千到两万 |
